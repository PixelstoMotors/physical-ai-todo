コード根拠（誰がどこを読み書きするか＝コードが正）

  • j0_lookup：VALID_PHASES = approach_pick / pick / approach_place / place_withblock / place_noblock。LOOKUP_PHASES から place_noblock を除外（L78）。place_noblock を渡すと ValueError（L258-262・detect 全失敗で XZ→j0 を持たない）。実質 place = place_withblock。pose_id は _load_arc が返す（L269）。
  • run_pick_place：ledger・run JSON とも KIOXIA（LOG_ROOT L134 / LEDGER_CSV_PATH L139）。KIOXIA 未マウントなら run 冒頭で ABORT（L1042-1046）し Mac 内蔵へ書かない。FK テーブルは読まない（L21 は「書き換えない」ガードコメントのみ）。
  • j0_sweep_scan：出力先 DEFAULT_OUTPUT_ROOT（L100）＝ .../dynamic_tracking_limits/logs/j0_sweep/。docstring L28 の ~/r2r2r-scripts/logs/j0_sweep/ は省略表記で、実体は dynamic_tracking_limits 配下。adopted/ への配置は別工程。

twin の構造詳細：列は ee_x,ee_y,ee_z,j0..j5（ee＝Unity 座標 m・関節＝度）。ee は Unity 内グリッパー先端 Brep の位置で ikpy では再現不可。点追加は Unity FKScanner 再実行のみ。

解決：real は「二重化」していなかった

以前「Mac working v3 と KIOXIA v2 が二重化」と疑っていた件は誤り。~/r2r2r-scripts/ 配下に ledger は 0 件（find 確認）。台帳の実体は KIOXIA の /Volumes/KIOXIA/r2r2r-data/runs/pick_place_ledger_v3.csv 単一で、コード（run_pick_place L139）もここを直書き。KIOXIA 専用・ローカル fallback なし。real は単一ソース・v3で確定。
